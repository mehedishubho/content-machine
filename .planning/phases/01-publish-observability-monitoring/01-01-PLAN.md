| queue worker → publish_events/log | Publish code (untrusted failure modes: exceptions, crafted content metadata) crosses into the observability store and JSON log stream |
| publish_events payload → third-party | Nothing crosses outward in this plan — payloads stay local; the rule prevents future leakage (Pitfall 4) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | PublishEventData payload / publish log channel | high | mitigate | DTO field whitelist (ids, stages, statuses, durations only); never toArray() config or client objects; no exception messages/stack traces in payloads |
| T-01-02 | Tampering | publish JSON log stream | low | mitigate | Monolog JsonFormatter escapes structural characters; payloads carry ids/statuses not raw content bodies — crafted content cannot forge log lines |
| T-01-03 | Repudiation | recorder write path | medium | mitigate | D-07 ordering: log line always fires before/beside the DB write; recorder failures swallowed so incidents cannot be masked by observability outages |
| T-01-SC | Tampering | composer install (this plan, Task 1) | high | mitigate | Package Legitimacy Audit table present in 01-RESEARCH.md; composer-only installs (sentry OK-approved in plan 01-04); no npm installs in this plan — no [ASSUMED]/[SUS] packages, so no blocking checkpoint here |
