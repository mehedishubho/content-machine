# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase surface (from D-17/D-18, locked):** one new dashboard page (`/dashboard/observability`)
with a success-rate visualization, failure and retry/lease-expiry counts, a period selector
(Today / 7 / 30 / 90 days, default 7), and a recent publish-outcomes list — plus one compact
success-rate stat card added to the existing dashboard home. Read-only reporting; no forms, no
mutations, no destructive actions. Watchdog alerts surface in Telegram, not in this UI.

| Success | `--good` #3f8b52 (dark #7cc48c) | Succeeded outcomes, success-rate bar segment, "Published" count number |

exclusively. Note (existing project trait, do not "fix"): `--accent` and `--bad` share the
same hue by design; they differ in role, and pills/bars distinguish via color-mix tinting.

## Page Contract (Phase 1)

Locked source: D-16 (denominator = content item), D-17 (page + home stat), D-18 (period
selector), D-19 (live SQL aggregates). Discretion area "dashboard page layout/component
breakdown" resolved here.

**Route & files**
- Route: `/dashboard/observability` in `routes/dashboard.php` (behind the existing
  `auth`+`verified`+`SetCurrentWorkspace` chain). Data via a read Action (per CLAUDE.md,
  thin controller → `BuildPublishObservabilityAction` or equivalent) → Inertia props.
- Page: `resources/js/pages/observability/index.tsx` (kebab page dirs, project convention).
- Nav: new entry in `mainNavItems` (`resources/js/components/app-sidebar.tsx`), title
  "Observability", lucide `Activity` icon, immediately after "Dashboard".
- Period state rides the URL query (e.g. `?period=7`) so a period is shareable/reloadable;
  switching triggers an Inertia partial reload of the metrics props only.

**Page layout (top → bottom)**
1. Head: `.home-h` "Observability" + `.dash-lead` lead sentence.
2. Period selector: `.tabbar` with four buttons (`aria-selected` on the active one; active
   styling is the existing raised-tile treatment — not an accent fill).
3. Counts row: `.stats` grid of four `.stat` tiles — Published (`--good`), Failed (`--bad`,
   default ink when 0), Retries (`--warn`), Lease expiries (`--warn`). Number = `.n` (28px
   serif), label = `.k`.
4. Success-rate block: the percentage figure at Display scale (28px serif, `--good`) beside a
   full-width stacked proportion bar, 12px tall, radius 999px — succeeded segment `--good`,
   failed segment `--bad`. **Chart approach (resolves RESEARCH.md Open Question 4): hand-styled
   CSS bars only — no chart library, no recharts.** Rationale: RESEARCH.md flags recharts SUS
   and recommends CSS bars as the default; a single stacked bar + count tiles satisfies D-17
   at single-operator volume, adds zero dependencies, and needs no `checkpoint:human-verify`.
   No axes, no tooltips.
5. Recent publish outcomes: `.dash-upcoming` list pattern — each row: human id (mono 12px,
   `--ink-faint`) | title (14px semibold, truncated one line) with a meta sub-line
   "Post · PostSyncer" or "Video · SocialReins" (mono 12px, `--ink-faint`) | outcome pill +
   timestamp (13px, `--ink-soft`, `Intl.DateTimeFormat('en-GB', …)` with the workspace
   timezone — same `timeLabel` pattern as dashboard home). Capped at the latest 20 outcomes
   with the cap note below the list.
6. Empty/error handling per the copy contract and the considerations table below.

**Home compact stat (D-17)**
- New `.dash-card` titled "Publish health", placed **first** in the existing `.dash-grid`.
- The grid changes from `repeat(3, minmax(0, 1fr))` to `repeat(auto-fit, minmax(240px, 1fr))`
  so four cards flow (4-across on wide screens, wrapping below 1100px per the existing media
  query).
- Three `.stat` tiles inside: success-rate figure (Display scale, `--good`; "—" in
  `--ink-faint` when no attempts), Failed (`--bad` when > 0), Retried (`--warn` when > 0) —
  all for the default 7-day period, matching the page default.
- Card header and stats link to `/dashboard/observability`.

**Outcome pill mapping** (new classes follow the existing `.pill.st-*` color-mix recipe):
- `st-succeeded` → `--good` · label "Succeeded"
- `st-failed` → `--bad` · label "Failed"
- `st-retrying` → `--warn` · label "Retrying"
- `st-lease` → `--info` · label "Lease expired"

**Accessibility**
- Period selector: real buttons with `aria-selected` and `aria-label` including the period
  ("Publish period: 7 days"); the active tab is communicated by state, not color alone.
- Success-rate figure: zero-attempt em dash carries visually hidden "No attempts" text.
- Outcome pills pair color with a text label (never color-only).
- Truncated titles/tokens carry `title` attributes with the full value.
- The page must render correctly in light and dark (token-driven; no raw hex).

## UI Considerations

> Shape-rooted UI *state* coverage. Empty-state and error-state COPY live in
> `## Copywriting Contract` above — this section covers state coverage and REFERENCES those
> rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 8 covered, 0 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | counts row + rate bar + outcomes list | ✅ covered | Zero attempts in the period renders the documented "No publish activity in this period." empty block and the success-rate figure as "—" |
| zero-one-many | success-rate figure + counts | ✅ covered | 0 attempts → "—"; 1 attempt → "100%" (or "0%"); counts show real zeros; singular/plural copy not needed (labels are count-neutral) |
| loading | period selector switch | ✅ covered | Inertia partial reload dims the metrics region to 60% opacity with layout preserved; no skeleton swap, no spinner flash |
| error | aggregate load failure | ✅ covered | Failed load renders an inline alert (ui kit `alert`) with the documented error copy and a Retry control; the page shell and period selector still render |
| partial | outcomes rows with missing optional fields | ✅ covered | Missing provider/group renders the meta sub-line with type only; missing title falls back to the human id |
| overflow | outcomes list at volume | ✅ covered | List is capped at the latest 20 outcomes with the documented cap note; further history is out of scope for v1 (90-day retention is queryable via SQL, D-19) |
| long-text | content titles + correlation ids | ✅ covered | Titles truncate at one line with CSS ellipsis; correlation ids (human id, job id, run token) render in mono with truncation and a `title` attribute carrying the full value |
| populated | typical single-operator volume | ✅ covered | 4 count tiles + one stacked bar + a ≤20-row list read at a glance without pagination or scroll juggling |
